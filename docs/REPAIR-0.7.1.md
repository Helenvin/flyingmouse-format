# 0.7.1 修复候选

修复扫描件正文缺失、OCR 方向错误、结构表格单元格错位，以及商店环境首次启动被 Office 准备阻塞的问题。尚未代表 Microsoft Store 审核或上架完成。

## 转换

- PDF 存在原生标题或印章时，仍检查页内栅格内容并补充 OCR。真正空白页不触发 OCR；合并时保留原生文字中的小数点等标点。
- OCR 校正倾斜，质量不足时重试布局与方向；质量过低明确失败，需复核的文字和金额显示双语提示。多页 TIFF 逐页处理。
- 扫描表格根据空间位置和文字对应识别结果，空白单元格保持空白；评分只统计有文字的单元格，原有质量阈值不降低。
- 区分模型缺失、资源超限、结果格式无效和引擎异常；在初始化模型前检查页数与累计渲染像素预算。

## 新格式

- SRT、VTT、ASS、SSA 字幕互转及 TXT 导出。样式、定位、精度损失有提示，无法表示的绘图或事件不静默丢弃。
- PDF 转 Markdown：文字、可判断的标题和简单表格。版式会重排，插图不作为可编辑 Markdown 图像还原。
- 图片通过 OCR 转可编辑 DOCX、Markdown。输出为识别文字，不宣称复原原图表格、插图和排版。

## 启动与体积

- Office 在独立 Worker 中准备，主界面先显示。只有 Office 任务等待准备，图片、文本和字幕可先使用。
- 缓存按引擎内容标识复用，暖缓存不每次运行转换；缓存损坏重新校验。失败保留界面与诊断。
- OCR WASM 核心只打包一份，保留支持的 SIMD/LSTM 变体。
- 默认完整版保留高级 PDF 结构识别。可选轻量版构建：`node scripts/build-windows-lite.js <输出目录>`，保留 Office、音视频、普通 PDF、轻量 OCR、图片转 Word/Markdown和字幕；高级扫描表格需要完整版。
- APPX 构建支持 `-StageDirectory`，把大型临时布局放到其他磁盘。

## 远程 CI 与原生引擎

`docstructure-engine-lock.json` 对应本地重建的 1.0.1 结构引擎。`ci-engines-v1.json` 目前仍引用旧的远程引擎资产；直接使用该资产运行 Windows CI，会在新引擎锁校验阶段失败。合并或发布前，必须上传匹配的新引擎资产并更新 CI 资产名称、SHA256，再运行远程门禁；不要删除或放宽锁校验以绕过差异。
